# PRD Global: Anti-Slop AI Engineering & Design Standard

[English](PRD_GLOBAL.md) | [Bahasa Indonesia](PRD_GLOBAL.id.md)

---

## 1. Executive Summary & Product Vision
This initiative is designed to eradicate **"AI Slop"**—cheap, generic, insecure, and chaotic code and UI generated by AI models (Google Antigravity, Claude Code, Cursor, Copilot, ChatGPT).

This standard transforms AI assistants from stochastic code generators into **Senior Principal Software Engineers & Lead Human Designers** committed to clean OOP architecture, zero-trust defense-in-depth security, consistent human-crafted visual aesthetics, and synchronized living documentation.

---

## 2. Problem Statement

1. **AI Slop Code:** AI frequently produces procedural spaghetti, copy-pasted code (*WET*), monstrous components (>500 lines), and ignores modern OOP patterns.
2. **Fragile Security:** AI easily overlooks server-side validation, leaves IDOR/BOLA vulnerabilities open, leaks credentials into source code, and neglects rate limiting.
3. **AI Slop UI/UX:** AI generates stereotypical interfaces with neon purple-blue gradients, unreadable glassmorphic blur, missing interactive states (*loading/empty/error*), and breaks existing design systems.
4. **Stale Documentation:** AI updates code and dependencies without synchronizing `README.md`, `.env.example`, or task specifications.

---

## 3. Goals & Non-Goals

### ✅ Goals
- Provide universal, agent-agnostic operational rules compatible with Google Antigravity, Claude Code, Cursor, Windsurf, GitHub Copilot, and ChatGPT.
- Enforce 100% adherence to clean OOP, SOLID, and modular architectures.
- Enforce defense-in-depth security covering Low to Critical vulnerabilities.
- Enforce human-crafted visual aesthetics that preserve existing design tokens.
- Establish living documentation synchronization as a mandatory prerequisite for task completion.

### ❌ Non-Goals
- Suppressing AI creativity in designing optimal algorithmic solutions.
- Adding excessive boilerplate or premature abstraction (*overengineering*) to trivial tasks.

---

## 4. Target Personas

1. **Senior Software Engineer / Tech Lead:** Wants AI acceleration without wasting hours cleaning up architectural technical debt.
2. **Product Designer / Frontend Lead:** Wants to guarantee that AI-generated UI respects design tokens, maintains accessibility, and avoids AI visual clichés.
3. **Security Engineer:** Wants assurance that every AI-generated feature has passed zero-trust threat modeling and input sanitization.

---

## 5. Core Requirements Matrix

| ID | Category | Requirement | Acceptance Criteria |
| :--- | :--- | :--- | :--- |
| **REQ-01** | **OOP & Reusability** | Code must follow clean OOP, SOLID, and modular patterns | No God Classes; dependencies injected via interfaces; files kept under 300 lines. |
| **REQ-02** | **Structure & Naming** | Feature-based / clean architecture with predictable naming | `kebab-case` filenames; no `_v2` or `temp` files; predictable directory layout. |
| **REQ-03** | **Hardened Security** | Complete protection from low-to-critical vulnerabilities | 100% parameterized queries; IDOR/BOLA checks on every mutation; active rate limiting; zero secrets in code. |
| **REQ-04** | **Anti-Slop Design & Responsiveness** | Human-crafted UI preserving existing design tokens with full multi-device responsiveness | No generic neon gradients; 8-pt grid adherence; 5 complete UI states; 100% responsive from 320px (all iPhone generations) to 4K ultra-wide; iOS Safe Area insets (`env()`) and dynamic viewport height (`100dvh`) compliant. |
| **REQ-05** | **Documentation Sync** | Documentation and README must be updated with code changes | Any new env var, command, or endpoint immediately updates `README.md` and `.env.example`. |
| **REQ-06** | **Testing & Verification** | Empirical verification before declaring tasks complete | Code verified via test runners or typecheckers; no claims of success without execution proof. |

## 6. Threat Modeling (STRIDE Analysis)

Systems implemented under this standard must evaluate these threat scenarios:
- **Spoofing Identity:** Token-based auth with secure signatures, CSRF protection, and HttpOnly cookies.
- **Tampering with Data:** Strict schema validation with DTOs; prevent mass-assignment exploits.
- **Repudiation:** Structured audit logging without leaking personally identifiable information (PII).
- **Information Disclosure:** Sanitized production error responses; zero stack traces exposed to clients.
- **Denial of Service:** Rate-limiting at the proxy and application layers; payload size restrictions.
- **Elevation of Privilege:** Strict role-based access control (RBAC) and resource ownership verification (anti-IDOR).
